自分のサイトに作品紹介のページを新設して、本文を Shippori Mincho B1（明朝体）で組みました。

上品な見た目になって満足していたのですが、ダークモードで開いたら**明らかに読みにくい。**

ゴシック（システムフォント）に変えたら解決しました。それ自体はよくある話です。
ただ気になったのが、**コントラスト比を測っても何も出ない**ことでした。文字色も背景色も変えていないので、当然といえば当然です。

「見にくい」のに「測ると問題ない」。この差がどこから来るのか調べたら、3つの要因が重なっていました。

## 前提: 明朝体は縦画と横画の太さが違う

そもそもの構造の話です。

明朝体は**縦画が太く、横画が細い**書体です。加えて画線の終わりに「ウロコ」と呼ばれる三角形の装飾が付きます。
筆で書いた文字の骨格をそのまま持っている形です。

ゴシック体は縦画と横画の線幅がほとんど同じで、装飾もありません。

この「太さの差が大きい」性質を、タイポグラフィではコントラストの高い書体と呼びます。欧文だと Bodoni や Didot が代表格です。

## 要因1: 細い線は、小さいサイズで消える

コントラストの高い書体には、よく知られた弱点があります。

**ヘアライン（極細の線）は、小さいサイズや低解像度で消えるか、途切れる。**

Bodoni や Didot が「見出し向きで本文には向かない」と言われるのは、これが理由です。
大きく組めば美しいけれど、本文サイズにすると細い線が保たないので。

日本語の明朝体も、程度の差はあれ同じ構造を持っています。縦画は残っても、横画のほうが先に厳しくなる。

自分のケースでは本文を15pxで組んでいました。**明朝は同じpxでも字面が小さく見える**ので、体感はもっと小さかったと思います。
16px + 行間1.95に変えたら、それだけでいくらか改善しました。

## 要因2: ダークモードでは、明るい文字が太く見える

ここからが本題です。

**irradiation illusion（放射錯視）**という現象があります。

明るいピクセルが暗い背景に対して置かれると、光が周囲ににじみ出て見えて、**文字が実際より太く見えます。**
画面の話だけではなく、看板のデザインでも古くから知られている効果だそうです。

白背景に黒文字のときと、黒背景に白文字のときで、**同じフォントウェイトなのに後者のほうが太く見える。**

これがダークモードでの1つ目の変化です。

## 要因3: font-smoothing が、逆方向に効く

もうひとつあります。

macOS では `-webkit-font-smoothing: antialiased` を指定すると、
サブピクセルレンダリングからグレースケールのアンチエイリアスに切り替わります。

その結果、**文字が細く描画されます。**

もともとこのプロパティが使われる背景には、こういう事情があります。
「macOSのネイティブなラスタライザは、暗い背景に明るい文字を描くときグリフを太らせる傾向がある」
それを打ち消して、デザイナーの意図した太さに近づけるために使われている。

自分のCSSにも、深く考えずに `antialiased` を入れていました。

## 3つが重なると何が起きるか

ここが今回いちばん腑に落ちたところです。

ダークモードの明朝体では、**縦画と横画で逆方向の変化が起きます。**

| | 元の状態 | ダークで起きること |
|---|---|---|
| **縦画**（太い） | しっかりした線 | irradiation で**滲んで太く**見える |
| **横画**（極細） | もともとギリギリ | `antialiased` で**さらに細く**なる |

明朝体という書体は、「縦が太く横が細い」という**比率でデザインされています。** その比率が、両側から別方向に引っ張られて崩れる。

太い部分はより太く、細い部分はより細く。文字の骨格が壊れて、**滲んでいるのに痩せている**という状態になります。

「なんか読みにくい」の正体はこれでした。

## なぜコントラスト比では検出できないのか

WCAG のコントラスト比は、**前景色と背景色の輝度の比**です。

今回、色は一切変えていません。だから比率も変わりません。基準を満たしたまま、読みにくい状態が成立します。

コントラスト比が測っているのは「色の差」で、今回起きているのは「**線の太さの見え方**」の問題でした。指標が現象を捉えていない。

アクセシビリティのチェックツールを通して緑が出ても、それは「色は大丈夫」と言っているだけです。
読みやすさの全部を保証してはくれない、というのは覚えておこうと思いました。

## 実際にやった対処

書体を使い分けました。

| 対象 | フォント |
|---|---|
| 見出し・作品名 | 明朝 / Cormorant Garamond のまま |
| 本文・説明文・リスト・数値 | ゴシック（システムフォント） |

**上品さは見出しが担っているので、本文をゴシックにしてもトーンは崩れませんでした。**

「見出しは明朝、本文はゴシック」は日本語Webの定番です。定番だから従っていたところがありましたが、理由が説明できると納得感が違います。
見出しは大きいので細い線が保つし、量が少ないので滲みも問題にならない。本文は逆です。

### 他に取れた選択肢

調べていて知ったのですが、**Variable Font の GRAD（Grade）軸**を使う方法もあります。

GRAD は、**文字幅を変えずに太さだけを調整できる**軸です。
ウェイト（`font-weight`）を変えると字幅が変わってレイアウトがずれますが、GRAD ならずれません。

ダークモードのときだけ GRAD を少し下げて、irradiation で太く見えるぶんを相殺する、という使い方ができます。

```css
@media (prefers-color-scheme: dark) {
  body {
    font-variation-settings: "GRAD" -50;
  }
}
```

対応しているフォントが必要なので今回は使いませんでしたが、書体を変えたくない場合の手としては覚えておきたいところです。

## まとめ

- 明朝体は**縦画が太く横画が細い**。この比率が書体の骨格になっている
- コントラストの高い書体は、**細い線が小サイズ・低解像度で消える**
- ダークモードでは **irradiation illusion** で明るい文字が太く滲んで見える
- `-webkit-font-smoothing: antialiased` は逆に**細くする**方向に効く
- 結果として**縦画と横画が逆方向に引っ張られ、書体の比率が崩れる**
- これは色の問題ではないので、**コントラスト比では検出できない**
- 対処は書体の使い分け（見出し明朝・本文ゴシック）か、Variable Font の GRAD 軸

「定番だから」で従っていたルールに理由があった、という話でした。
理由が分かると、例外を作っていい場面も判断できるようになるので、調べてよかったと思っています。
