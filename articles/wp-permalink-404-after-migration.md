## はじめに

WordPressをサブドメインや別サーバーへ移行したあと、トップページは表示されるのに固定ページや投稿ページがすべて404になる現象に遭遇しました。

All-in-One WP Migration（以下AIO）でデプロイした直後の話です。「DBは入ってるのに記事だけ見えない」と一瞬青ざめましたが、結論からいうと10秒で直りました。

## 発生した現象

- トップページ: 200 OK
- 投稿ページ・固定ページ: すべて404
- WP管理画面: 普通にログインできる
- DB / メディアファイル: 移行済み

データは入っているのに、ページだけ見えない状態でした。

## 原因

`.htaccess` のリライトルールが本番側で再生成されていなかったのが原因でした。

WordPress のパーマリンクは、見た目の URL（例: `/sample-page/`）を内部で `index.php?p=123` のような形に書き換えて動かしています。この書き換えを担っているのが `.htaccess` の `mod_rewrite` ルール。

AIO Migration は記事・設定・メディアは持っていきますが、`.htaccess` の同期は保証していないようです。`.git` フォルダが持ち込まれないのと同じで、サーバー側で再生成しないと空 or 旧パターンのまま残ります。

## 解決方法

WP 管理画面で **設定 → パーマリンク設定 → 「変更を保存」を押すだけ**。

- 設定値は変えなくていい
- 保存ボタンを押すと内部で `.htaccess` が自動再生成される
- 10秒で復帰

WP-CLI が使える環境なら以下でも同じ効果が得られます。

```bash
wp rewrite flush --hard
```

## まとめ

- 移行後の404は DB 欠損ではなく、ほぼ `.htaccess` 再生成漏れ
- パーマリンク設定の「変更を保存」が `.htaccess` 再生成のトリガー
- AIO Migration は `.htaccess` を持ち越さない前提で運用する

知っていれば10秒、知らないと数十分溶ける罠でした。同じ場面で焦った人の検索結果に届けば。
