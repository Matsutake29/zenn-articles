自分のブログや Zenn の記事を X（Twitter）で告知するために、Python で自動投稿ツールを作って運用しています。告知の出し方で1つ迷ったところがあって、半年運用して数字が出たので書きます。

## 本文に URL を混ぜず、返信にぶら下げる設計にした

```python
# 本文を投稿し、2投稿目以降とURLを順に返信としてぶら下げる。
# リンクを本文に混ぜず末尾の返信に分けるのは、アカウント全体のリンク投稿比率を
# 下げるため。リンク付き投稿は伸びにくい傾向がある。
tweet_id = xpost.post_tweet(entry.texts[0], env)
...
if entry.url:
    reply_id = xpost.post_tweet(entry.url, env, reply_to=prev_id)
```

1件の告知が、**本文の投稿と URL の投稿の2つに分かれます**。理由は「リンク付き投稿は伸びにくい」という一般論でした。自分で測った数字ではありません。

## 測り方

X API v2 で直近45日の投稿を取り、主投稿と返信を `conversation_id` で紐づけて、**返信のインプレッションを主投稿のインプレッションで割りました**。これが「本文を見た人のうち、URL まで表示された人の割合」です。

```python
# tweet.fields に conversation_id を入れないと紐づけられない
params = {
    "tweet.fields": "conversation_id,public_metrics,created_at",
    ...
}
```

`tweet.fields` に `conversation_id` を入れる必要がある点は、地味ですが引っかかりどころでした。既定では返ってきません。

## 結果

| | 値 |
|---|---|
| 到達率の中央値 | **28.6%** |
| 平均 | 32.0% |
| 対象 | 31件 |

**本文を100人が見たとして、URL の返信まで表示されたのは29人。** 7割には URL が届いていません。

## 守れていたもの

リンクの有無で本文どうしを比べると、こうなりました。

| | 件数 | 中央値 imp | いいね率 |
|---|---|---|---|
| リンク付き（告知の本文） | 31 | 98 | **2.78%** |
| リンクなし（単発の投稿） | 35 | 100 | 1.91% |

**本文の側は落ちていません。** 狙いどおり、リンクの存在で本文が沈むことは避けられている。いいね率はむしろ告知のほうが高い。

## この設計は「本文の到達を守って、リンクの露出を7割捨てる」取引だった

良い取引かどうかは、**まだ判断できません**。

理由は、App-only 認証の API では**リンククリック数（非公開指標）が取れない**からです。「本文を守れた」は測れたのですが、「リンクを捨てて何を失ったか」はクリック数が無いと分からない。

「リンクを本文に入れると伸びない」のほうも、自分で測った数字ではなく一般論のまま使っています。本文にリンクを入れた場合の比較群を作っていないので、本当に沈むのかは確かめていない。

**実測できたのは片側だけ**で、トレードオフの半分しか見えていない状態です。

## 数字が出て初めて、自分が何を選んでいたか分かった

設計した時点では「リンク投稿比率を下げる」という目的しか見ていませんでした。到達率29%という数字が出て、それが**7割を捨てる選択**でもあったと分かった。

返信に分けるべき、とも、本文に入れるべき、とも言えません。ただ、一般論で決めた設計がどういう取引になっていたかは、測ったら数字で出た。次は本文にリンクを入れた群を作って、反対側も測るつもりです。

計測は X API v2（Free プラン・App-only）。集計は2026-08-14 時点の45日間・自分のアカウントのみ。
