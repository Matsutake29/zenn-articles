:::message
2作目のポートフォリオとして「Hubpin」（分散した発信を1か所に集めるハブサイト）を作りながら書いています。カードを ↑↓ ボタンで並び替える機能の話です。

- リポジトリ: https://github.com/Matsutake29/hubpin
- Next.js（App Router） + Supabase + Tailwind CSS

並び替えのボタンを実装したとき、手順書には「押した直後にフォーカスが消える」と予想が書いてありました。

実際は消えず、連続で押せました。`key={item.id}` のおかげだと推測したのですが、**確かめていなかった**ので、`key={index}` に変えて同じ操作をしてみました。

## 検証の手順

3番目のカードの「↑」ボタンにフォーカスを当ててから押し、移動後に `document.activeElement` がどのリスト項目に属するかを見る。`key` を変えて2回実行。

## 結果

| `key` | 移動の結果 | **フォーカスの行き先** |
|---|---|---|
| `key={item.id}` | 3番目のカードが2番目へ | **移動したカードの「↑」**＝ カードに付いてきた |
| `key={index}` | 同じ | **別のカードの「↑」**＝ 位置に残った |

**順序はどちらも正しい。** 見た目の並びだけを見ていると、差が出ません。

## 実害の形

`key={index}` では、押した直後にフォーカスが**隣のカードのボタン**に乗ります。そのまま Enter を押すと、**意図しないカードが動く**。

- キーボードだけで操作する人には、連続操作がそのまま誤操作になる
- マウスだと押すたびに位置を見るので、気づかないまま通る

`key={index}` の壊れ方は「順序がずれる」ではありませんでした。**「間違ったものを操作させる」**です。

## なぜそうなるのか

`key` が決めているのは「**どの DOM ノードが同じものか**」で、フォーカスは**ノードに乗っています**。

- `key={item.id}` → React はノードを作り直さず**移動**させる。フォーカスも一緒に動く
- `key={index}` → 同じ位置のノードが**別のデータを表示する**。フォーカスは位置に残る

内部で何が起きているかは観察からの推測ですが、`activeElement` の行き先はこの説明と一致していました。

## この記事の立ち位置

`key={index}` を避ける理由として広く説明されているのは、**state がずれる**ことと**差分更新の効率**の2つだと思います。

今回見たのは**フォーカスの連続性**で、既存の説明とは別の層でした。「key は速さの話」と覚えていたので、操作の連続性を決めているとは思っていませんでした。

## 「おかげだと思う」で止めなかった

手順書の予想が外れて、連続で押せた。その理由を `key` だと推測したところまでは自然でしたが、そこで止めると「なんとなく動いている」のままです。

`key={index}` に変えるのは1分で済みました。実験のためだけに変えて、`git checkout` で戻しています。1分で推測が実測に変わるなら、やったほうがいい。今回それで、手順書の予想がなぜ外れたかまで説明がつきました。

環境: React 19.2.8 / Next.js 16.3.0。検証は 2026-08-14。
