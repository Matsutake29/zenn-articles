## `pnpm install` の最後で止まった

Next.js の公式チュートリアルを進めていて、最初のインストールで詰まりました。
手順どおりに打っただけです。

```
ERR_PNPM_IGNORED_BUILDS  Ignored build scripts: bcrypt@5.1.1, sharp@0.34.5
Aborting installation.
```

パッケージの取得自体は終わっていて、最後に中断されています。
`bcrypt` と `sharp` の名前が出ているので、そのあたりで失敗したのだろうと思って調べ始めました。

結論から書くと、**失敗ではありませんでした。**

## 何と何がズレていたか

教材の手順には `pnpm` のバージョンが書かれていませんでした。
インストールの案内があるだけです。

```bash
npm install -g pnpm
```

これで入るのは、その時点の最新版です。自分の環境では **11.18.0** が入りました。

一方、教材が書かれた時点の pnpm は当然もっと前のバージョンです。
そして pnpm は **v10 で、依存パッケージのビルドスクリプトを既定で実行しなくなっています。**

`postinstall` のようなスクリプトは、インストールしただけでコードが走る仕組みです。
そこに悪意のあるコードを仕込む攻撃が知られているので、
**実行してよいかを利用者が明示的に決める**方式に変わりました。

教材が古くなったというより、**足元の既定値が入れ替わっていた**、というほうが近いです。

## エラーではなく、仕様どおりの停止だった

メッセージを読み直すと、失敗とは書いていません。

> Ignored build scripts: bcrypt@5.1.1, sharp@0.34.5

**「無視した」**と言っています。
`bcrypt` も `sharp` もネイティブのバイナリを使うパッケージなので、
インストール時のビルドが要ります。それが走っていない。

そして同時に、設定ファイルにこういうものが書き込まれていました。

```yaml
# pnpm-workspace.yaml
allowBuilds:
  bcrypt: set this to true or false
  sharp: set this to true or false
```

`set this to true or false` ——**「あなたが決めてください」**と書かれた穴が空いています。

pnpm の公式ドキュメントにも、こう書かれています。

> Packages not listed in `allowBuilds` are disallowed by default and treated as unreviewed

**列挙されていないものは既定で不許可で、「未レビュー」として扱われる。**
エラーで止めているのではなく、**判断されていない状態で先に進めないようにしている**わけです。

`true` に書き換えればインストールは通ります。

```yaml
allowBuilds:
  bcrypt: true
  sharp: true
```

## 設定の書き方はさらに変わっていた

調べているときに混乱したのがここです。

検索して出てくる記事の多くは、`package.json` にこう書けと言っています。

```json
{
  "pnpm": {
    "onlyBuiltDependencies": ["bcrypt", "sharp"]
  }
}
```

これは **v10 の書き方**でした。
v11 では `onlyBuiltDependencies` と `neverBuiltDependencies` が **`allowBuilds` に統一**され、
`pnpm-workspace.yaml` に書く形になっています。

つまり同じ問題について、**手元に出た指示（`allowBuilds`）と、検索で出てくる解決策（`onlyBuiltDependencies`）が
別の名前**という状態でした。
古い書き方から移すためのコマンドも用意されています。

```bash
pnpx codemod run pnpm-v10-to-v11
```

「教材が想定するバージョン」「実際に入るバージョン」に加えて、
**「検索で出てくる記事が想定するバージョン」**まで、それぞれ違っていたことになります。

## 見分け方として持ち帰ったこと

「教材どおりにやったのに動かない」を分解すると、多くはこの形をしています。

1. 教材が書かれた時点のツールのバージョン
2. いま `install` すると入るバージョン
3. 検索で出てくる解決策が前提にしているバージョン

エラーメッセージを読む前に、まず**この3つがどこを指しているか**を見るようになりました。
`--version` を打つだけなので10秒で終わります。

今回の場合、メッセージ自体が丁寧で、**何を無視したか・どこに書けばいいか**まで出ていました。
「エラーが出た」と身構えて検索に飛ぶ前に、出力を最後まで読めばよかったな、というのが正直なところです。

## 持ち帰り

- **pnpm は v10 から、依存パッケージのビルドスクリプトを既定で実行しない。** サプライチェーン対策
- `ERR_PNPM_IGNORED_BUILDS` は失敗ではなく、**判断されていないものを実行しないための停止**
- **v11 で設定キーが `allowBuilds`（`pnpm-workspace.yaml`）に統一された。**
  v10 の記事に出てくる `onlyBuiltDependencies` とは別名
- 「教材どおりなのに動かない」は、たいてい教材・手元・検索結果の**3つのバージョンがずれている**
