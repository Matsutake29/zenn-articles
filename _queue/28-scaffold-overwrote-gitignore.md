ポートフォリオ2作目の環境構築で `npx create-next-app@latest .` を実行したら、
**既存の `.gitignore` が追記ではなく丸ごと置き換えられていました。**

前の工程で書いていた2行が消えています。

```gitignore
CLAUDE.local.md
.claude/
```

AIエージェント用のローカル設定ファイルです。個人メモなので管理外にしていました。

消えたこと自体は3分で直りました。書いておきたいのは、**なぜ消えたことに気づけたのか**のほうです。

## 気づけたのは「差分」があったから

きっかけは、エディタのエクスプローラに付いた `U`（Untracked）マークでした。
除外していたはずのファイルが、追跡対象として画面に出てきた。この変化で気づいています。

`.gitignore` の中身を見比べたわけではありません。**状態が変わったことに気づいただけ**です。

ここで、順序を逆にしていたらどうだったかを考えました。

実際にやった順序はこうでした。

1. GitHubで空のリポジトリを作る
2. `.gitignore` を書いてコミットする
3. `create-next-app` で雛形を入れる

この順序だと、雛形による上書きが**差分**として出てきます。だから気づけました。

もし逆に「雛形を作ってから `git init`」だったらどうなるか。

- `create-next-app` が生成した `.gitignore` が、そのまま初期状態になる
- `CLAUDE.local.md` の除外は「消えた」ではなく「**最初から無い**」
- 差分が存在しないので、誰も教えてくれない

**gitは「変化」しか教えてくれません。初期状態が正しいかどうかは判定してくれない。**

当たり前のことを書いている気もするのですが、自分は「まずリポジトリを作る」を
順序が決まっている儀式のようなものだと思っていました。実利があるとは考えていませんでした。

## 先に1コミット置いておくと、以降のズレが全部見える

「最初にリポジトリを作る」の意味が、今回で少し変わりました。

**自分の意図を先に1コミット置いておくと、それ以降のズレが差分として浮きます。**
逆に、何も置かないまま外部ツールに初期状態を作らせると、そのツールの前提がそのまま自分の前提になります。

GitHubの New repository に「README / .gitignore / LICENSE を先に作る」オプションがあるのも、
同じ発想なのだろうと思いました。空のリポジトリを空のまま始めない、ということかと。

## 復旧したあと、置き場所を1回動かした

上書きされたぶんは末尾に書き足して戻しました。そのとき `.env.example` の扱いも足しています。

現在の `.gitignore` は該当箇所がこうなっています。

```gitignore
# env files (can opt-in for committing if needed)
.env*
!.env.example

（中略）

# 個人メモ・セッション設定（git管理外）
CLAUDE.local.md
.claude/
```

`.env*` は `create-next-app` が生成した行です。これが `.env.example` まで巻き込むので、
`!.env.example` で打ち消しています。

最初は復旧のついでにファイル末尾へ足していたのですが、`.env*` から40行近く離れていて、
何を打ち消しているのか読めませんでした。翌日、`.env*` の直後へ移動しています。

**`.gitignore` は後の行が勝つ**ので、末尾でも動作としては同じです。
ただ、動くことと読めることは別でした。

## 余談: 雛形を作る前の分岐も見ておく

`create-next-app@16.3.0` は、1問目が「推奨デフォルトを使うか」の2択になっていました。

```
TypeScript, ESLint, No React Compiler, Tailwind CSS, No src/ directory, App Router, AGENTS.md
```

`No src/ directory` が自分の設計と逆だったので、customize を選んで `src/` ありにしました。

雛形の中身を目視するというルールを工程に入れていたのですが、
それが**生成後ではなく生成前の分岐で先に効いた**格好です。

そのまま Enter を押していたら、ディレクトリ構成の違いに気づくのは
何ファイルか置いたあとになっていたと思います。
