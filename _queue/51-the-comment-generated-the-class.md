VS Code の Tailwind CSS IntelliSense が、ある警告を出し続けていました。

> `text-[var(--c-base)]` は `text-base` に短縮できます

自分は「それは受け入れてはいけない提案だ」と判断して却下しました。**この判断の理由が間違っていた**、というのが前半で、**もっと予想外のことが見つかった**、というのが後半です。

## 最初の判断（間違い）

`@theme` に `--color-base`（背景色）を定義していました。

Tailwind のデフォルトには `--text-base`（フォントサイズ 1rem）があります。`node_modules/tailwindcss/theme.css` に実在するのを確認しました。だから「提案どおりに直すと、色の指定がフォントサイズの指定に変わる」と考えて、警告を1件残すことにしました。

理由をコメントに書いて、そのまま数週間放置していました。

## ビルド出力を見たら、逆だった

改めてビルド出力を確認したら、こうなっていました。

```css
.text-\(color\:--c-base\), .text-base { color: var(--c-base) }
```

**2つは同じルールに統合されています。** `--color-base` が `--text-base` に勝っていました。提案どおりに直しても、色のまま正しく動く。

危険は反対方向にありました。**`--color-base` を定義した時点で、Tailwind 標準の `text-base`（フォントサイズ）が使えなくなっている**。将来サイズのつもりで書いたものが、黙って色になる。

避けた判断は結果的に無害でしたが、理由が間違っていました。「危ないから避けた」が当たっていても、危なさの中身が違えば次の判断を誤る、というのがここで残ったことです。

## 予想していなかった発見: コメントからも CSS が出ていた

ビルド出力に `.text-base` があるのは分かりました。では、それはどこから来たのか。

`text-base` を検索したら、**ソースのコメントの中にしか書かれていませんでした**。「これは使うな」という説明文です。

```tsx
// 🚨 text-base は使わないこと。--color-base と衝突して色になる
```

それが CSS に出力されていました。

**Tailwind v4 はファイルをテキストとして走査するので、コメントか文字列かを区別しません。** 「使うな」と書いた説明が、まさにそのクラスを生成していた形です。

## 解決: 名前を変えた

| 案 | 判断 |
|---|---|
| **`--color-base` → `--color-canvas` に改名** | ✅ 採用。衝突そのものが消え、標準のサイズ指定が本来の意味に戻る |
| 今のまま | 警告が残り、将来サイズのつもりで書く事故も残る |
| 提案どおり `text-base` | 動くが、読む人が必ずフォントサイズだと誤解する |

使用箇所は3つだけだったので、影響が小さい今が一番安く直せました。

検証は、ビルド後の CSS で `text-base` が **0件**になること、エディタの警告が **2件 → 0件**になること。両方確認しています。

新しいコメントは、**日本語だけで書いてクラス名を1つも含めていません**。上の発見があったので。

## コードを説明するために書いた文字列が、コードとして読まれる

静的解析なら「これはコメントだ」と分かります。テキスト走査には、その区別がありません。

Tailwind v4 が速さのためにパースを捨てている設計なのは理解できます。その代償がここに出た、というだけで、ツールの落ち度ではないと思っています。IntelliSense の警告も正しく動いていました。プロジェクト固有の命名を知らないだけです。

自分の側で持ち帰ったのは、**コメントに書くクラス名は、書いたぶんだけ CSS に出る**ということ。説明文で「`text-base` は使うな」と書きたくなったら、その `text-base` 自体を書かない形にする必要がある。

環境: Tailwind CSS 4.3.3 / Next.js 16.3.0。`theme.css` の行番号は版で動くので書いていません。
