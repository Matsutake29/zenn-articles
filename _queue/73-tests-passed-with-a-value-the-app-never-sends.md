フォームの URL 項目に、形式チェックを足そうとしました。

そのとき気づいたのですが、**既存のテスト11本は、その変更を当てても全部通ります**。そして本番では、URL を使わない種類のカードが作れなくなる。

## テストが渡す値と、アプリが渡す値が違った

| | 渡している値 |
|---|---|
| テスト | **キーを省略**（`undefined`） |
| アプリ | **空文字**（`''`） |

アプリ側は、フォームから値を組み立てるときにこう書いていました。

```ts
url: String(formData.get('url') ?? '')
//   ↑ 未入力でも '' になる。undefined にはならない
```

スキーマ側は `.optional()` が付いています。ここで2つの値の扱いが分かれます。

- `undefined` → **`.optional()` で素通り**。形式チェックまで到達しない
- `''` → **形式チェックが走って落ちる**

テストは `undefined` しか渡していないので、`z.url()` を足しても11本とも通ります。URL を使わないカードのテストは全部「キーを省略」で書いてあった。アプリは一度もそういう渡し方をしません。

## 形式チェック自体の実害は小さかった

`z.url()` が無くても、壊れたリンクが表に出るだけです。急いで足す理由はありませんでした。

ただ「**テストが `''` を通していない**」という事実は、形式チェックを足すかどうかと独立して、今この瞬間も真でした。将来 `url` に何か制約を足すたびに、同じ形で踏みます。`z.url()` は最初の1回にすぎない。

だから先に直したのはテストのほうでした。スキーマは後回しにしています。

```ts:__tests__/item-schema.test.ts
test('note は url が空文字でも通る', () => {
  ...
  url: '',
  ...
})
```

これがあると、次に誰かが `z.url()` を素で足した瞬間に CI が落ちます。穴を塞ぐというより、**穴を踏んだら止まる**ようにした形です。

## そのうえで形式チェックも入れた

テストで止まる状態にしてから、`z.url()` を入れました。ただし単体では入れず、空文字を許す形にしています。

```ts:src/lib/schemas/item.ts
// z.url() 単体にしないこと。actions.ts が String(formData.get('url') ?? '')
// を渡すので、url を入力しない note / feed では '' が来て必ず落ちる。
url: z.union([z.url({ error: 'URLの形式で入力してください' }), z.literal('')]).optional(),
```

`.optional()` は残しています。`undefined` も `''` も通る形です。

### zod 4 の union はどうエラーを返すか

`z.union([z.url(), z.literal('')])` にしたとき、不正な URL のエラーが `invalid_union` にまとめられるのか、`z.url()` 側のエラーがそのまま出るのかで、テストの書き方が変わります。

一時ファイルで同じ構造を再現して流しました。

```text
❌ link + 不正なURL: [{"code":"invalid_format","path":["url"]}]
✅ link + 正しいURL: success
✅ note + 空文字:    success
✅ feed + 空文字:    success
✅ note + url省略:   success
```

**`invalid_union` ではなく `invalid_format`。`path` は `['url']` のまま。** zod 4 の union は、片方のブランチのエラーをそのまま出していました。

これを先に測っておかないと、テストが落ちたときに原因が `union` なのか `refine` なのかを切り分けられません。

## テストが緑なのは「壊れていない」を意味しない

「**テストが渡した値の範囲では壊れていない**」しか意味しない、というのが今回の着地でした。

テストはあったし、11本とも実装を見ていました。ただ、確かめる仕組み自体が、確かめる対象と違う入力を使っていた。`undefined` と `''` は `.optional()` の前では同じに見えるので、テストを書いた時点では区別する理由がありませんでした。

「テストを書け」という話にはならないと思っています。書いてあった。値が違っただけです。

環境: zod 4.4.3 / Next.js 16.3.0。
