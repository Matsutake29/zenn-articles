:::message
2作目のポートフォリオとして「Hubpin」（分散した発信を1か所に集めるハブサイト）を作りながら書いています。

- リポジトリ: https://github.com/Matsutake29/hubpin
- Next.js（App Router） + Supabase + Tailwind CSS

自分のポートフォリオサイトを、素のHTML/CSSからNext.jsのアプリに作り直しています。
見た目はそのまま移すつもりでいました。ところがトップページのレイアウトだけは、移植を諦めることになりました。

Bento Grid です。大きさの違うカードを弁当箱のように敷き詰めるレイアウト。
静的サイトのときは何も問題がありませんでした。それが、DBからカードを出す設計にした瞬間に成立しなくなりました。

先に書いておくと、Bento Gridに問題があったわけではありません。
**静的サイトでの最適解が、動的化したら最悪解になっていた**、という話です。

## 手書き時代はこう書いていた

```css
.l-hub__grid {
  grid-template-columns: repeat(4, 1fr);
  grid-template-areas:
    "main-1   main-1   main-2  main-2"
    "sub      sub      sns-1   sns-2"
    "sub      sub      sns-3   sns-3"
    "roadmap  roadmap  roadmap roadmap";
}
```

4列のグリッドに、7枚のカードを名前で配置しています。
HTML側では1枚ずつ `style="--card-area: main-1;"` と手で指定していました。

書いていて不便を感じたことはありません。**カードが7枚で固定だったからです。**
増えないものを手で並べるのは、そもそも手間になりません。

## アプリ化したら成立しなくなった

作ろうとしていたのは、DBに登録したカードを可変枚数で出して、並び替えもできるものです。
ここで `grid-template-areas` と噛み合わなくなりました。

`grid-template-areas` は、カードの枚数と並びが固定であることを前提にした書き方です。
カードが1枚増えたら、エリア表を書き換えることになります。

これは、**手でHTMLを書き換えていた問題が、CSSに移動しただけ**でした。
CMS化したはずなのに、更新のたびにコードを触る状態は何も変わっていない。

管理画面を作る意味がなくなるので、ここで手が止まりました。

## 同じ問題に、別の入口から2回ぶつかった

面白かったのは、この問題に2回、違う角度から到達したことです。

| 見ていたもの | 出てきた問題 |
|---|---|
| CSSの実装 | エリア表が可変枚数と両立しない |
| UIの使い勝手 | PCとスマホで列数が変わると並び順が変わる。編集画面でレイアウトを組ませるのも手間 |

最初は別々の課題としてメモしていました。片方はCSSの話、もう片方は管理画面の話だと思っていたからです。

並べてみたら原因は一つでした。**カードにサイズ差を持たせている**ことです。

サイズ差があるから配置を指定する必要があり、配置を指定するから枚数が固定になる。
UI側も同じで、サイズ差があるから列数が変わったときに並びが崩れます。

原因が1個だと分かると、対処も1個で済みます。逆に言えば、片方だけ直しても解けませんでした。

## 検討して、選ばなかった案

まず、レイアウトを維持したまま可変にする方向を考えました。

- **`sort_order` から `grid-template-areas` をサーバー側で生成する**
  並び替えのたびに再計算が必要になります。カードを1枚動かしたときに他のカードがどう動くのか、
  自分でも説明できる気がしませんでした
- **7枚固定のまま、可変にしない**
  見た目は守れますが、作ろうとしているものと矛盾します

CSSのテクニックも2つ試して落としました。

- **`grid-auto-flow: dense`**
  空いた隙間に後ろのカードを詰めてくれます。ただしDOMの順序と見た目の順序がズレるので、
  タブキーでの移動が画面上を飛び回ることになります
- **`order: -1` で展開中のカードを先頭に出す**
  並び順を保ちたいという目的と逆行しています

## 結論: サイズ差をやめて、差は「展開」で表現した

最終的にこうしました。

- カードは全部同じサイズにする
- 押すと**そのカードだけ全幅に展開**する（`grid-column: 1 / -1`）
- 情報量の差は、大きさではなく「開くかどうか」で表現する

スマホは元々1列なので、展開しても縦に伸びるだけです。
**PCとスマホで並び順が変わらない**という、UI側の問題も同時に消えました。

副産物がひとつありました。編集画面から「カードの大きさ」という設定項目が消えたことです。
ユーザーに決めてもらう項目が1つ減りました。

サイズ差をやめると決めたときは、見た目を捨てる判断のつもりでいました。
実際には、レイアウトの都合をユーザーに押し付けるのをやめた、という形になっています。

## 移す前に気づけたのは運が良かった

この判断は、実装に入る前の設計工程で出ています。

もし見た目をそのまま移植してから可変枚数に対応しようとしていたら、
`grid-template-areas` を生成するコードを書いてから捨てることになっていました。

静的サイトをCMS化する場面はよくあると思います。
そのときに移植リストへ載せるかどうかは、**「増えたときに手で書き換えるものが残っていないか」**で
見るようになりました。

Bento Grid は7枚固定の静的サイトでは正解でした。前提が変わったことに気づいていなかっただけです。
