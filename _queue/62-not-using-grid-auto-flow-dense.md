カードをグリッドで並べて、タップしたカードだけが全幅に展開する形にしました。

展開すると、**前の行に隙間が残ります**。
3列で並んでいて2番目を開くと、1番目の隣が空きます。

CSS にはこれを埋める仕組みがあります。

```css
.grid {
  grid-auto-flow: dense;
}
```

`dense` は、後ろにある小さいアイテムを前の穴に詰めてくれます。
見た目の隙間は消えます。

使いませんでした。

## `dense` が動かすのは見た目だけ

`dense` が変えるのは配置であって、**文書の順序ではありません**。
MDN の自動配置ガイドにも、そう書かれています。

> グリッドの他の並べ替えと同様に、これは論理的な順序を変更するものではありません。例えば、タブの順序は文書の順序に従います。

タブキーで移動する順序は、HTML の中で要素が並んでいる順です。
これは HTML の仕様で決まっていて、CSS では動きません。

`dense` を入れると、**見えている並びと、タブが進む順序が食い違います**。
画面の左上にあるカードへ移動したつもりが、フォーカスが画面の右下へ飛ぶ。
キーボードで操作している人にとっては、次にどこへ行くか予測できない状態になります。

関連する達成基準は2つあります。

| 基準 | 何が壊れるか |
|---|---|
| WCAG 2.4.3（Focus Order） | フォーカスの移動順が意味を保てなくなる |
| WCAG 1.3.2（Meaningful Sequence） | 読み上げの順序と視覚の順序が乖離する |

同じ注意は `order` プロパティにも書かれています。
CSS で並びを動かす手段は、だいたいこの問題を持っています。

## 却下した3案

隙間を埋める方法は他にもあったので、並べて見ました。

| 案 | 却下した理由 |
|---|---|
| `grid-auto-flow: dense` | DOM 順と視覚順がズレる |
| `order: -1` で展開カードを先頭へ移動 | 位置は予測できるようになるが、**並び順を保つという目的と逆行する**。ユーザーが決めた順序を勝手に変えることになる |
| 行の直下にパネルを出す（画像検索のような形） | **列数を JS で検知して行末を計算する**必要がある。ブレークポイントごとに列数が変わるので、リサイズにも追従させることになる |

3つ目は実装としては一番見た目が良い方法ですが、CSS で済んでいたものに JS を足すことになります。
グリッドの列数は CSS のメディアクエリで決まっているのに、その値を JS 側でもう一度持つ形になるのが引っかかりました。

## 結局、何も書かないのが答えだった

採ったのは「隙間をそのままにする」です。

```tsx
<li className={`flex flex-col ${isOpen ? 'col-span-full' : ''}`}>
```

展開したカードに `grid-column: 1 / -1`（Tailwind の `col-span-full`）を当てるだけです。
1列目から最終列までを占めるので、そのカードだけが全幅になります。

`dense` は書いていません。
**書かないことが実装**でした。

判断としては珍しいケースだったと思います。
アクセシビリティの対応は、たいてい手間が増える方向に効きます。
今回は**「正しい」と「安い」が同じ側**にありました。

隙間が空いていることを許容するほうが、実装も短く、キーボード操作も壊れない。
迷う理由がほとんどありませんでした。

## 2025年に、この制約を外す仕様が出た

調べていて分かったのですが、**この問題を解決する CSS が実装され始めています**。

`reading-flow` と `reading-order` というプロパティで、視覚的な並びにタブ順を合わせられます。
Chrome 137（2025年5月）で使えるようになりました。

```css
.grid {
  grid-auto-flow: dense;
  reading-flow: grid-rows;  /* タブ順を視覚順に合わせる */
}
```

ただし、2026年9月の時点で実装しているのは Chrome だけです。
Safari と Firefox では効きません。

自分のサイトで使うかというと、まだ使わないと思います。
**効かないブラウザで壊れるのが、キーボード操作という見えにくい部分**だからです。
自分の環境では確認できてしまうので、壊れていることに気づけません。

ただ、「`dense` は使えない」という言い方は、もう正確ではなくなりました。
全部のブラウザに入れば、隙間を埋めつつタブ順を保てます。

## 埋めない、を選べるようにしておく

書き終えて思ったのは、**穴が空いていることを許容できるかどうかを先に決めておくと、選択肢が1つ増える**ということでした。

「隙間は埋めるもの」と決めていたら、3案のどれかを実装していたはずです。
3つとも、それぞれ別の負債を抱えます。

今回の画面では、隙間が1つ空いていても困りません。
カードが一覧できることが目的で、隙間なく敷き詰めることは目的ではなかった。
そこを確かめたら、実装する必要そのものが消えました。
