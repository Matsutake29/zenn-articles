2作目のポートフォリオとして「Hubpin」（分散した発信を1か所に集めるハブサイト）を作りながら書いています。

- リポジトリ: https://github.com/Matsutake29/hubpin

Supabase から1件取ってきて、無ければ 404 を返すだけのページを書きました。

```ts
const { data: item } = await supabase
  .from('items')
  .select('title, type, url, description, visible')
  .eq('id', id)
  .maybeSingle()

if (!item) notFound()
```

`error` を受け取っていません。よく見る書き方で、間違いというわけではない。ただ、RLS を入れた自分のプロジェクトでは**3つの別々の事態が全部同じ404になっていました**。

## 同じ404に潰れていた3つ

| 実際に起きていたこと | 種類 | 正しい扱い |
|---|---|---|
| RLS が0行を返した（他人の行） | **正常** | 404 で合っている |
| `select` に無いカラムを書いていた | **バグ** | 404 にしてはいけない |
| UUID に変換できない文字列が URL に来た（`22P02`） | **不正なリクエスト** | 404 にするかは設計判断 |

3つとも画面は同じです。

```ts
if (error) console.error(error)   // ← これを1行足した
```

足した瞬間に `22P02 invalid input syntax for type uuid: "guest"` が出ました。**足すまで、これが起きていること自体に気づけませんでした。**

RLS の0行は PostgREST 側ではエラーになりません。行が無いのと同じ扱いで返ります（`.maybeSingle()` の場合。`.single()` だと0行は `PGRST116` というエラーになるので、見え方が変わります）。だから `error` を捨てていても、RLS の正常系は正しく404になる。問題は、**エラーがある側も同じ404になっていた**ことでした。

## 「エラーではなく不可視」と「エラーがあるのに見ていない」は別物

RLS の設計は「他人の行は存在しないように見える」で、これは意図した挙動です。エラーにしないのが正しい。

一方で、カラム名の誤りや不正な UUID は、DB 側がエラーとして返しています。それを受け取らずに捨てていたのは、設計ではありません。バグでした。

**画面が同じなので、ログでしか区別できません。** `error` を受け取るのは例外処理のためというより、**同じ画面になる3つを区別するため**でした。

## RLS が効いている証明にも、同じ壁が立った

これは検証する側にも同じ形で出ました。「他人のカードを開いたら404になること」を確かめようとして、**2回外しました**。

| 開いた ID | 何が起きたか | 何を証明したか |
|---|---|---|
| ユーザー名の文字列 | UUID に変換できず `22P02` | **何も**（DB エラー側の確認になった） |
| 他人の `profiles.id` | `items` にその ID は無い | **何も** |
| 他人の `items.id` | **行は実在するのに0行で返る** | RLS が隠した |

3つとも画面は同じ404です。「404が出た」だけでは何も確かめられていませんでした。存在しないものと、見えないものが区別できない。**「不可視」の核心はここにあって、検証する側も同じ壁に当たります。**

RLS が効いている証明には、「実在する他人の行」を開いて0行になることを見る必要がありました。

## RLS を使う設計は、0行を握りつぶす書き方と相性が悪い

RLS を使うと「0行が正常」になります。だから `data` だけを見て `notFound()` する書き方が自然に見える。

ただ、その書き方は「エラーがあっても0行と同じ」を同時に選んでいます。RLS を入れた時点で、`data` だけの分割代入は意味が変わっていました。よくある書き方が悪いという話ではありません。**自分のプロジェクトの前提が変わったことに気づいていなかった**、という話です。

環境: Next.js 16.3.0 / @supabase/supabase-js 2.112.1 / Supabase（PostgreSQL）。今は `{ data: item, error }` で受け取り、`error` はログに出す形にしています。
