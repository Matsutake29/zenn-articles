WordPressの受託でコーディングを2年やってきて、いまフロントエンドに軸足を移そうとしています。
TypeScriptを一通りやって、Next.js に入る手前あたりです。

学習していて気づいたのですが、**新しいものを覚えるとき、自分は毎回ゼロから概念を入れようとしていました。**

それで何度か手が止まったので、やり方を変えました。**既に持っている地図（WordPress）に重ねる**ことにしたんです。

書き出してみたら、思ったより多くのものが対応しました。
同じようにWeb制作からフロントエンドに移ろうとしている人には、そのまま渡せる形になっていると思うので置いておきます。

## スタック全体

| モダンスタック | WordPressでいうと |
|---|---|
| **Next.js** | WordPress本体（ルーティング + テンプレート + レンダリング） |
| **Supabase** | MySQL ＋ ユーザー管理 ＋ メディアライブラリ |
| **Vercel** | レンタルサーバー（ConoHaなど） |

### Next.js ≒ WordPress本体

「URLを受け取って、対応するテンプレートを選んで、データを埋めてHTMLを返す」という役割が同じです。

**違うところ**: WordPressはCMSなので、管理画面とDBまで込みで1つです。
Next.jsは表示側だけを担当して、データの置き場所は別に用意します。だから Supabase が要る。

### Supabase ≒ MySQL + ユーザー管理

データを保存する場所、という点では同じです。

Supabaseは中身がPostgreSQLで、そこに認証・ストレージ・リアルタイム通信が乗っています。
WordPressで言えば、MySQL に `wp_users` の仕組みとメディアライブラリが最初からセットになっている感じ。

**違うところ**: WordPressのDBはテーブル構造が決まっていますが（`wp_posts` に何でも入る）、Supabaseは自分でテーブルを設計します。
ここは自由なぶん、考えることが増える側です。

### Vercel ≒ レンタルサーバー

デプロイ先、という意味では同じ位置です。

**違うところ**: レンタルサーバーは「置いた場所で動く」ですが、Vercelは「pushしたらビルドして配る」です。
ビルドの工程が挟まるのと、配信がCDN経由になるのが大きな違いでした。

## 機能レベルの対応

### Server Components ≒ `page.php` でのサーバー処理

これが一番腑に落ちた対応です。

WordPressのテンプレートでは、こう書きます。

```php
<?php
$posts = get_posts(['posts_per_page' => 5]);
foreach ($posts as $post) : ?>
  <article><?php echo esc_html($post->post_title); ?></article>
<?php endforeach; ?>
```

**サーバーでDBから取って、HTMLを組み立てて返す。** JavaScriptは関係ありません。

Server Components がやっていることも、構造としては同じでした。

```tsx
export default async function Page() {
  const posts = await getPosts()
  return posts.map(p => <article key={p.id}>{p.title}</article>)
}
```

Reactを学び始めたとき「全部ブラウザで動くもの」だと思っていました。
そのため、サーバーで実行されるコンポーネントという概念が最初まったく入りませんでした。
`page.php` と同じだと分かってから、急に普通のことに見えました。

**違うところ**: `page.php` はページ単位ですが、Server Components は**コンポーネント単位**です。
1つのページの中に、サーバーで動く部品とブラウザで動く部品が混在できる。ここはWordPressに対応するものがありません。

### Server Actions ≒ フォームの送信処理

フォームを送ってサーバーで処理する、という流れが同じです。

WordPressだと Contact Form 7 のようなプラグインを使います。
あるいは `admin-post.php` にアクションを登録する。

```php
add_action('admin_post_my_form', 'handle_my_form');
```

**エンドポイントを用意して、そこに送信する**という構造です。

Server Actions は、関数に `'use server'` を付けるとその関数自体が呼び出し先になります。
エンドポイントを自分で作らない。

**違うところ**: 対応づけとしては Contact Form 7 より `admin-post.php` のほうが近いです。
ただ「フォームを出して、送って、サーバーで受ける」という体験としてはCF7のほうが馴染みがあるので、最初の理解としてはそちらで掴みました。

### ファイルベースルーティング ≒ テンプレート階層

`app/blog/[slug]/page.tsx` が `/blog/xxx` になる。

WordPressの `single.php` `archive.php` `page-contact.php` と同じです。
**ファイルの名前と場所がURLを決めます。**

**違うところ**: WordPressのテンプレート階層は「投稿タイプと条件から自動で選ばれる」ルールで、覚えるものが多いです。
Next.jsはディレクトリ構造がそのままURLなので、こちらのほうが素直だと感じました。

### `layout.tsx` ≒ `get_header()` / `get_footer()`

共通の外枠を1箇所で持つ仕組みです。

WordPressでは各テンプレートの先頭と末尾で `get_header()` `get_footer()` を呼びます。
Next.jsでは `layout.tsx` が子を包む形。

**違うところ**: `layout.tsx` はネストできて、階層ごとに別のレイアウトを重ねられます。
WordPressでこれをやろうとすると、テンプレートパーツを条件分岐で組み合わせることになります。

### 静的生成 ≒ HTMLキャッシュ系プラグイン

ビルド時にHTMLを作っておいて、リクエスト時は配るだけ、という考え方です。

WordPressでも WP Super Cache などが同じことをやります。
動的に生成したHTMLをファイルに保存して、次からはそれを返す。

**違うところ**: WordPressのキャッシュは「動的なものを後から固める」ですが、Next.jsの静的生成は**最初から固める前提で設計する**点が違います。
順序が逆というか、思想が逆かもしれません。

## 対応しないもの

正直に書いておくと、対応表が作れなかったものもあります。

- **Hydration**（サーバーで作ったHTMLに、ブラウザでJavaScriptを紐づける工程）
- **クライアントコンポーネント / サーバーコンポーネントの境界**
- **型（TypeScript）**

WordPressは基本的に「サーバーで作って終わり」なので、ブラウザ側で続きをやる概念がありません。ここは新しく覚えるしかない部分でした。

**地図に載らないものがあると分かること自体が、地図の効用**だと思っています。全部が対応するなら学ぶ必要がないので。

## 実務経験は「遅れ」ではなく「地図」だった

学習を始めた当初、2年の実務経験は**アドバンテージにならない**と思っていました。
WordPressはモダンな環境とは違うし、覚え直しだ、と。

やってみたら逆でした。

新しい概念に出会ったとき、**既に持っている地図に重ねられます。** ゼロから概念を入れる人より、掴むのが速い。

「フレームワークに呼ばれる」というのを初めて理解したのも、WordPressのフック（`add_action`）でした。
自分が書いた関数が、自分の知らないタイミングで呼ばれる。あれをずっとやっていたので、フレームワークという言葉の意味が体で分かっていました。

React学習中の人は無数にいますが、**WordPress実務の視点でモダンスタックを読み替えている人**はあまり見かけません。
差別化というより、同じ立場の人に渡せるものがある、という感覚です。

## まとめ

- Next.js ≒ WordPress本体、Supabase ≒ MySQL + ユーザー管理、Vercel ≒ レンタルサーバー
- **Server Components ≒ `page.php`**。サーバーでDBから取ってHTMLを返す流れは同じ
- Server Actions ≒ `admin-post.php` のアクション。エンドポイントを作らない点が違う
- ファイルベースルーティング ≒ テンプレート階層。Next.jsのほうが素直
- **Hydration とコンポーネントの境界は対応するものがない**。ここは新規に覚える
- 実務経験は覚え直しの負債ではなく、**重ねるための地図**だった
